把 PyTorch 模型跑在浏览器里（ONNX.js 学习笔记）

视频信息：

  • 标题：How to Run PyTorch Models in the Browser With ONNX.js
  • 作者：Elliot Waite
  • 链接：https://www.youtube.com/watch?v=Vs730jsRgO8

训练好的 PyTorch 模型可以转成 ONNX 格式，再用 ONNX.js 这个 JavaScript 库直接在浏览器里做推理，不需要任何后端服务器。

一、模型放浏览器还是放后端？

视频开头用两张表对比了两种方案。我自己看下来，核心区别可概括为：浏览器换来了速度和用户隐私，后端换来了算力和模型隐私。

浏览器端的好处

  1. 推理快、响应快：数据不用发到服务器再等返回，省掉了网络延迟。视频里作者现场演示了一个 MNIST 手写数字识别的页面，每画一笔模型就实时更新预测结果，几乎是”边画边猜”。
  2. 部署和扩展都简单：网站只需要一堆静态文件，用户量暴涨也不用加后端节点、不用做负载均衡。
  3. 可以离线用：因为不依赖服务器，所有推理代码在第一次加载页面时就已经下载好了，断网也能跑。
  4. 用户隐私：用户的输入数据（可能是敏感数据）始终留在本地设备上，不会被发送、不会被截获。

后端的好处

  1. 加载快：模型文件不用下载到用户设备，首次打开页面的速度快。
  2. 推理时间稳定且能跑大模型：服务器算力固定、性能可控；用户设备的性能参差不齐，大模型在低端手机上可能根本跑不动。
  3. 模型隐私：模型文件留在服务器上，用户看不到计算图和参数。这和”用户隐私”正好是同一枚硬币的两面——放浏览器保护用户的数据，放后端保护你自己的模型（商业机密）。

什么情况下不该放浏览器

  • 模型太大，首次下载页面要等太久；
  • 模型不算大，但在用户设备上算一次推理太慢；
  • 模型本身需要保密。

三、用TensorFlow.js 还是 ONNX.js？

把训练好的模型变成 JavaScript 能用的东西，有两条路线：

路线 能力 适合场景
TensorFlow.js 推理 + 训练 想在浏览器里继续训练模型
ONNX.js 只能推理 只想用模型出结果（更简单、性能更好）

作者的结论是：只做推理就选 ONNX.js，理由是更简单、性能更好。他用 ResNet50 做了基准测试，对比 TensorFlow.js、Keras.js、ONNX.js 三者跑一次推理的耗时（柱子越矮越好，黄色是 ONNX.js）：

可以看到不管 CPU 还是 GPU，ONNX.js 都是最快的那一个。测试者还附了两条说明：

  1. Keras.js 在 Edge 上不支持 WebGL；
  2. Keras.js 和 TensorFlow.js 在任何浏览器上都不支持 WebAssembly（所以 CPU 上被 ONNX.js 的 WASM 后端甩开）。

四、ONNX 是什么

ONNX 全称 Open Neural Network Exchange（开放神经网络交换）。官网的定义是：

ONNX 是一种用来表示机器学习模型的开放格式。它定义了一组通用的运算符（机器学习/深度学习模型的构建块）以及一种通用的文件格式，让 AI 开发者可以在各种框架、工具、运行时和编译器之间使用模型。

ai给我的通俗解释：ONNX 就像模型世界的”通用插头”。PyTorch、TensorFlow 等框架各自内部格式不通用，但都能把模型导出成 ONNX 格式——里面同时描述了模型的结构和参数。导出之后，任何支持 ONNX 的运行时都能加载它，ONNX.js 就是 JavaScript 世界的这样一个运行时，浏览器、Node.js、内嵌网页视图的 App 里都能跑。

视频里的转换脚本叫 convert_to_onnx.py，完整代码如下：

  1. 导入网络结构：Net 是训练脚本 train_mnist_model.py 里定义的网络类，转换时必须用和训练时完全相同的结构，不然参数装不进去。
  2. 实例化 + 装参数：Net() 先建一个随机初始化的模型，再由 load_state_dict 把训练好的参数文件 pytorch_model.pt 装进去——到这一步模型和训练结束时一模一样。
  3. model.eval()：切换到推理模式。关键作用是关掉 Dropout——训练时 Dropout 随机丢弃神经元防止过拟合，但推理时我们希望结果是确定的，必须把它关掉。
  4. dummy_input = torch.zeros(1, 1, 28, 28)：一份形状和真实输入一致的假数据（1 张图、1 通道、28×28 像素）。数值全零无所谓，但形状必须对——因为 torch.onnx.export 要”真的跑一遍”模型来记录计算图。
  5. torch.onnx.export(...)：把模型连同计算图导出成 onnx_model.onnx 文件，verbose=True 会在控制台打印出导出的计算图细节，方便确认结构对不对。

六、在浏览器里加载和推理

网页端只需要一个 HTML 文件，通过 CDN 引入 ONNX.js 后，核心代码：

  1. 引入库：一行 <script> 从 CDN 加载 ONNX.js，不需要 npm、不需要构建工具。
  2. 建会话 + 加载模型：new onnx.InferenceSession() 创建推理会话，await sess.loadModel('./onnx_model.onnx') 把上一节导出的模型文件读进来。两步都是异步的，所以要 await。
  3. 造输入：new onnx.Tensor(new Float32Array(28 * 28), 'float32', [1, 1, 28, 28]) —— 784 个 float32 数值，形状 [1, 1, 28, 28]，和导出时 dummy_input 的形状一一对应。视频里先造全零的假输入来验证链路通不通，真实使用时这 784 个数就是画板上 28×28 图像的灰度值。
  4. 跑推理：await sess.run([input])，返回一个输出张量的集合（Map）。
  5. 取结果：outputMap.values().next().value 从 Map 里取出第一个（也是唯一的）输出张量，它的 data 就是 10 个数字各自的预测概率。

视频开头演示的手写画板就是这么实现的：每次笔迹更新，把画布内容变成 784 个灰度值喂进去，立刻拿到 0~9 的预测。

七、总结

  1. 这个视频推翻了 “模型必须放在服务器上”这种想法，并且把”用户隐私 vs 模型隐私”这对取舍讲得很清楚。
  2. ONNX 这种”通用中间格式”的思路值得记住——解决的是”框架各说各话”的问题，和编译器中间码、USB 接口标准本质上是一类设计。
  3. 如何选型：要在浏览器里训练用 TensorFlow.js，只做推理用 ONNX.js。
